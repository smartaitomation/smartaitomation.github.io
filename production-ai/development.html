RAG / search example

The answer sounds right. The source is wrong.

Company knowledge, support search and internal assistants.

The input

“How long do I have to return an order?”

Old policy · 30 daysCurrent policy · 14 days
The failure
“You have 30 days to return it.”

An expired page outranks the current policy. The model confidently repeats it.

The target output
“The current return window is 14 days.”

Include the current policy citation. Ask for missing context when eligibility is unclear.

↳

What to improve

Version the sources. Filter expired policies. Keep rules and exceptions in the same chunk.

Check the resultCurrent evidence found · supported answers · correct abstentions

What your engineers practise

Build the dataset

Tag questions by intent, source version and answerability. Include conflicting policies, duplicate pages and questions with no answer.

Find the failure

Inspect retrieval before rewriting the prompt. Compare chunk boundaries, keyword + semantic search and reranking.

Test the improvement

Score evidence retrieval separately from answer correctness. Check citations and have reviewers validate the scoring rules.

Documents example

One invoice works. The next layout breaks it.

Invoices, contracts, forms and scanned documents.

The input

Invoice fields: subtotal 120.00 · tax 24.00 · total 144.00

Layout A · clear tableLayout B · totals in the footer
The failure
total: 120.00

The extractor selects the subtotal when the supplier changes the layout.

The target output
total: 144.00

Link the value to its source. Route missing or ambiguous fields for human review.

↳

What to improve

Label each field. Test different layouts. Validate types, totals and row relationships.

Check the resultField accuracy · missing values · time spent correcting

What your engineers practise

Build the dataset

Sample suppliers, layouts, scan quality and languages. Label field values and source locations; distinguish absent fields from extraction errors.

Find the failure

Separate OCR, layout, field mapping and validation errors. Review results per field and document type, not only one overall score.

Test the improvement

Compare OCR and extraction approaches on held-out layouts. Check totals and row associations, then measure the remaining review effort.

Email replies example

A polished reply misses half the question.

Support drafts, account requests and operations inboxes.

The input

“Where is my order, and can I change the delivery address?”

Two requests · tracking + address change
The failure
“Your order arrives tomorrow. I’ve updated the address.”

The reply invents a delivery date and claims an action that never happened.

The target output
“Please share your order number so we can check delivery and whether an address change is still possible.”

Answer both requests. Escalate exceptions. Claim an action only after it succeeds.

↳

What to improve

Split the request into intents. Check order status and policy. Confirm actions through tools.

Check the resultIntent coverage · unsupported claims · editing time

What your engineers practise

Build the dataset

Tag conversations by every intent, required context and permitted action. Include multi-question threads, missing details and exceptions.

Find the failure

Trace intent detection, retrieved context, tool results and the final reply. Check whether the system had enough information to answer.

Test the improvement

Evaluate completeness and factual support separately. Test handoff and tool failures; measure staff editing time as well as response quality.
