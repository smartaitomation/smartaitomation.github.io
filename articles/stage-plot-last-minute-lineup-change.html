Update a stage plot after a last-minute lineup change

By Smart Automation SRLOctober 21, 20267 min read

Identify what actually changed, revise the stage diagram and input list together, then reconcile every removed and added source against channels, monitor needs and packing. Send one clearly dated replacement packet and ask the venue to confirm outstanding decisions. Changing an instrument icon alone does not define its audio connections.

Freeze the last sent version before making the replacement

Name the show, date, venue and last sent revision. Work from that exact baseline rather than an older tour sketch. Write the lineup change in plain language: who leaves, who joins and which instruments or outputs are actually used. Keep the original available for comparison.

Yamaha’s sound-check guidance describes an input list with source names, mixer channels and microphone/DI details, plus a stage plot with matching identifiers. The revision method here is our original practical handoff. It does not configure a venue console or replace the engineer’s patch decisions.

Ask the incoming player about actual outputs. A keyboard icon could represent a mono output, stereo pair or no audio source in a particular setup. Do not invent connections, DI boxes, phantom-power settings or spare capacity. Record unresolved facts as questions for the responsible people.

Worked revision: one guitar source becomes a stereo keyboard

Fictional show revision R2 used four input channels: lead vocal on 1, guitar DI on 2, bass DI on 3 and kick microphone on 4. Before this show, the guitarist is replaced by a keyboardist whose left and right outputs have been confirmed. R3 therefore requires five channels, with the final house patch still to be agreed.

The count is 4 − 1 + 2 = 5. Retaining 1, 3 and 4 in this example makes the change visible; it is not a rule that every venue must keep those channel numbers. The venue may map requested sources differently. Label requested and confirmed patch columns separately.

If only four usable inputs are available, R3 has an unresolved capacity conflict. Do not silently drop the right output or assume mono is acceptable. Agree a supported alternative with the player and engineer, document that decision, then revise both the input list and diagram. Check monitor requirements separately; five input channels do not imply five monitor mixes.

Check the consequences beyond the channel count

Remove the old player and add the new player in the correct performer-perspective stage position. Review the changed source labels, cables, DI requirements, stands, power and monitor requests against what the band brings and what the venue has confirmed. Retained equipment may still be needed elsewhere; removing one source does not justify deleting every stand or cable.

Add a revision legend naming R3, the change time and the changes from R2. Mark the old packet superseded in your own files and communicate which replacement is current. A sent message proves neither receipt nor agreement; keep acknowledgement and unresolved decisions separate.

Before departure, compare diagram, source list, patch, pack list and advance message. Read every new source across those views. A table that says five channels and a diagram showing only the old guitar is still inconsistent. The linked advance-email guide helps summarize the agreed revision without replacing the packet.

Questions answered

Does replacing a guitar with a keyboard keep the same input count?

Only if the actual confirmed sources support that. This example adds a stereo pair and removes one source.

Are requested channel numbers the house patch?

Not until confirmed. Keep the distinction visible.

Is the new packet approved when I send it?

No. Record receipt, decisions and outstanding questions separately.
